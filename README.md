# Active Directory Enterprise-Certificate-Services
This document presents the complete technical implementation record for an Active Directory Certificate Services (AD CS) to Encrypting File System (EFS) project, conducted in an on-premises healthcare domain lab environment. The project establishes a functional internal Public Key Infrastructure (PKI) from scratch — deploying an Enterprise Root Certificate Authority, enrolling domain users for EFS-capable certificates, and demonstrating cryptographically enforced file confidentiality.
The lab environment simulates a healthcare organisation's IT infrastructure: a Windows Server 2022 domain controller running Active Directory Domain Services (AD DS), DNS, and AD CS under the domain healthcare.local. A Windows 8 client machine joined to the domain serves as the endpoint for certificate enrollment and EFS testing.

The project demonstrates a complete, end-to-end cryptographic trust chain: Active Directory establishes the user's identity; AD CS issues a trusted certificate binding that identity to a public/private key pair; EFS uses that certificate to encrypt a file so that only the certificate holder (ali.test) can decrypt it; and a second domain user (other.test) — despite having a valid domain account — cannot open the encrypted file because they do not possess ali.test's private key. This is a fundamental demonstration of the principle that cryptographic access control operates independently of, and provides stronger guarantees than, traditional NTFS permission-based access control.
